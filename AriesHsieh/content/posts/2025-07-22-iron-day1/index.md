# 與 iOS 開發的相遇

身為從律師轉職的軟體工程師，我正式投入軟體開發領域也已將近兩年。當初決定轉換跑道時，首先自學 Python，接著逐步接觸資料庫、API 等後端相關技術。後續有幸進入 AppWorks School（現已更名為 AiWorks），展開 iOS App 開發相關訓練，最後順利進入金融業 IT 部門就職。

進入公司後，工作內容相當多元，除了 iOS 專案的開發和維護之外，還涵蓋後端維運、SQL 撰寫，以及 Splunk、Kong APIM 等系統管理。雖然實際從事 iOS 開發的時間不多，但我始終對這塊領域抱有熱情。能創造出生動且實用的應用，讓我非常有成就感。因此剛進公司時難免對無法專注於 iOS 略感失落，但我相信廣泛接觸各類技術對軟體開發者而言絕對是資產，多元學習有助於長遠發展。即便不想設限自己專注於單一技術，心中依舊渴望精進 iOS，特別是 SwiftUI。

目前公司專案以 Objective-C 和 UIKit 為主，儘管我自己已用 SwiftUI 開發並上架過 app，但這次鐵人賽是絕佳機會，能讓我更扎實深入地學習和實踐 SwiftUI。

# 初入 DevOps 世界

在公司任職期間，我有幸參與了 Azure DevOps 的導入過程。起初，這對我來說只是另一個需要學習的工具：使用 Wiki 記錄文件、用 Work Items 追蹤任務、透過 Pipeline 編譯 .ipa 檔案，以及透過 Pull Request 進行程式碼審查。每一個環節都需要遵循特定流程，例如 Pipeline 需要主管審核才能部署。

這些經驗讓我逐漸理解到 DevOps 不僅僅是工具的使用，更是一種促進開發、測試和部署流程順暢的文化。即使是一人開發的專案，建立良好的 DevOps 實踐依然重要：

- **版本控制：** 使用 Azure Repos 管理程式碼，建立分支策略
- **自動化測試：** 配置 Pipeline 自動執行單元測試
- **持續整合：** 每次提交程式碼後自動編譯並檢查
- **持續部署：** 自動將測試通過的版本部署到 TestFlight
- **文件管理：** 使用 Wiki 記錄開發過程和技術文件

這次的系列文章，我將結合 SwiftUI 開發與 DevOps 實踐，從建立基礎專案開始，一步步實現自動化的開發流程。

# 專案靈感 — 生活中的真實痛點
每當看到新聞報導「哪條道路幾 K 處發生事故」或臨時想找「台 19 線 89K」位置時，才發現里程標實際在地圖上的位置很難查找。以往我都只能靠 Google 街景慢慢翻找里程牌，過程相當繁瑣。因此，我希望透過這次專案打造一款 app，讓使用者能夠直接輸入公路里程標（公里數），即時在地圖上定位對應位置，真正解決這項生活痛點。

# 寫這些文章的目的，給誰看？

我的想像主要是：

- 有基本程式底子，想了解一下 SwiftUI。
- 想把個人或小型專案帶進 Azure DevOps，用 Boards 管進度、用 Pipelines 跑測試跟打包，至少要有一條跑得起來的 CI/CD，把最小流程跑起來。
